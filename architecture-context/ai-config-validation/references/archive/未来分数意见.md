你这个“未来价值入口”方案，我觉得 **比直接增加 futureScore 更符合你现在引擎阶段**。

因为你现在不是做完整博弈搜索，而是：

```
当前局面
↓
生成组合
↓
评分排序
↓
选择最高
```

在这种架构下，直接引入未来模拟：

```
当前评分 + 下一回合期望价值
```

会迅速膨胀：

* 需要状态预测
* 需要手牌概率
* 需要对手模型
* 需要搜索深度

复杂度会爆炸。

所以你提出：

> 判断局势不是太劣势，给与额外分数，让他先出

本质是：

**用启发式先手价值（initiative value）近似未来收益。**

这个方向正确。

---

但是我建议不要叫 `futureScore`，因为它不是未来价值。

更准确：

```
initiativeScore
```

或者：

```
tempoScore
```

因为它表达的是：

> 当前没有必要立即防守时，保持主动权的价值。

---

你的公式可以变：

```
TotalScore =
 Σ(
   baseScore
   + extraScore
   + ruleScore
   + initiativeScore
 )
 -
 remainingCostPenalty
 -
 comboPenalty
```

---

## initiativeScore 的触发条件

不要简单：

```
局势好 => 加分
```

否则AI会无脑抢节奏。

应该：

### 1. 优势局

例如：

```
我方场面:
强

敌方:
弱

血量:
安全
```

奖励：

```
+2 ~ +5
```

鼓励：

* 铺场
* 压制
* 抢资源

---

### 2. 均势局

小奖励：

```
0 ~ +2
```

避免过度保守。

---

### 3. 劣势局

关闭。

甚至：

```
initiativeScore = 0
```

因为这时候需要：

* 解场
* 找翻盘
* 保命

---

## 但是注意一个坑

你这个机制会和 `remainingCostPenalty` 打架。

比如：

5费回合。

方案A：

打5费大怪：

```
base=12
initiative=3

total=15
```

方案B：

打1费过牌：

```
base=5
initiative=3
remainingPenalty=-6

total=2
```

结果：

AI还是不考虑过牌。

所以：

initiativeScore 解决的是：

> 出牌倾向

不是：

> 未来资源价值

---

我建议以后保留扩展：

```
ruleScore
    |
    +-- tacticalScore
    +-- setupScore
    +-- initiativeScore
```

现在先实现：

```
initiativeScore
```

以后如果发现：

AI缺少：

* 过牌
* 减费准备
* combo等待

再增加：

```
setupScore
```

## 数值建议

你的 ruleScore:

```
普通:
2~10

战略:
12~18

绝杀:
20+
```

那么：

initiative 不应该超过普通规则。

建议：

```
优势:
+3

均势:
+1

特殊:
+5
```

不要超过：

```
+6
```

否则AI会：

> 因为优势局想压制，忽略明显高价值动作。

## 我觉得你当前模型最终形态应该是

```
TotalScore

=
Σ(
  baseScore        // 卡牌基础价值
+ extraScore       // 单卡品质
+ ruleScore        // 当前战术
+ initiativeScore  // 主动权
)

- remainingPenalty // 法力浪费
- comboPenalty      // 组合副作用
```

这个层次已经比较像实际游戏AI：

* baseScore = 卡牌价值
* extraScore = 卡牌质量
* ruleScore = 当前目标
* initiativeScore = 局势倾向
* penalty = 资源浪费

---

所以你的想法不用改，甚至比我之前提 futureValue 更适合你的架构。

我只建议改名和限制：

> 不要把它定义为未来价值，而定义为“局势允许时的主动权奖励”。

这样后续扩展不会把语义搞乱。你现在这个引擎其实已经开始从“评分函数”往“启发式评估函数”方向走了。
