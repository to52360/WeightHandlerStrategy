意思是：**如果你现在没有正式运行、没有存量配置兼容包袱，那就应该改。**

不要保留 `containsKey(_sourceId) && containsKey(_operatorId)` 作为主设计。它只是“已经有旧 JSON / 旧 UI /
旧配置不能动”时的过渡办法。你现在既然还没正式跑起来，就没有必要背这个兼容成本。

我建议直接改成显式模型：

```kotlin
sealed interface ConditionPayload {
    data class ConditionRef(
        val conditionId: String,
        val refId: String = conditionId,
        val args: Map<String, Any> = emptyMap()
    ) : ConditionPayload

    data class OrthogonalRef(
        val sourceId: String,
        val operatorId: String,
        val refId: String = "${sourceId}_${operatorId}",
        val args: Map<String, Any> = emptyMap()
    ) : ConditionPayload
}
```

然后 `ConditionRegistry.build(...)` 不再猜：

```kotlin
fun build(payload: ConditionPayload): ConditionLogic {
    return when (payload) {
        is ConditionPayload.ConditionRef ->
            build(payload.conditionId, payload.args)

        is ConditionPayload.OrthogonalRef -> {
            val assembler = conditionAssembler ?: error("ConditionAssembler is not configured in this context")
            assembler.assemble(payload)
        }
    }
}
```

`ConditionAssembler` 也不应该再从 `args` 里拿 `_sourceId/_operatorId`，而是直接接收：

```kotlin
fun assemble(ref: ConditionPayload.OrthogonalRef): ConditionLogic {
    val source = dataSources[ref.sourceId] ?: error("DataSource not found: ${ref.sourceId}")
    val operator = operators[ref.operatorId] ?: error("Operator not found: ${ref.operatorId}")
    ...
}
```

这样边界就清楚了：

- `ConditionRef` = 老式/手写条件，一个 conditionId 对应完整逻辑。
- `OrthogonalRef` = 新式正交条件，由 `DataSource + Operator + args` 拼出来。
- `args` 只放算子参数，比如 `threshold`、`race`，不再混入系统识别字段。
- AI 生成时也不会疑惑：它选的是 `sourceId` 和 `operatorId`，不是往一个 Map 里塞魔法字段。

所以我的明确建议是：**改。现在正是改的时候。**
