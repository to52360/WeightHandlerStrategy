## 1. 升级后的 V2.1 六分量算式与防凑卡机制

打分组合总有效得分 (TotalScore) 遵循以下完整算式：

$$\text{TotalScore} = \sum_{i=1}^{n} \Big (\text{baseScore}_i \times \lambda^{i-1} + \text{extraScore}_i + \text{ruleScore}_i \Big) + \text{initiativeScore} - \text{remainingCostPenalty} - \text{comboPenalty}$$

```
                                  打分组合总得分 TotalScore
                                              │
        ┌─────────────────────────────────────┼─────────────────────────────────────┐
        ▼                                     ▼                                     ▼
【1. 衰减基础分 baseScore】            【2. 静态额外分 extraScore】            【3. 动态规则分 ruleScore】
第 i 张卡 baseScore * λ^(i-1)          单卡超模/副作用配置                     评估树叶子节点 ConstantScore
(λ = 0.85 衰减，防止多卡凹函数膨胀)     (-3.0 ~ +5.0，负分卡豁免 comboPenalty) (支持负向规则分，如满血治疗-5.0)
        │                                     │                                     │
        ├─────────────────────────────────────┼─────────────────────────────────────┤
        ▼                                     ▼                                     ▼
【4. 局势主动权 initiativeScore】       【5. 剩余法力惩罚 remainingPenalty】    【6. 非线性组合惩罚 comboPenalty】
基于局势量化矩阵与打出张数轻微挂钩        由 PenaltyWeight * √rem * ratio^β 算   (n-1)^1.5 * w 非线性剧增扣分
(优势/均势且非劣势局触发，上限 +6.0)     (PenaltyWeight / CostWeight 比值0.6~0.7) (对多卡垃圾堆砌施加重罚)
```

- **空过基准 (Pass Baseline)**: $\text{TotalScore} (\text{pass}) = 0.0$。当所有组合 $\text{TotalScore} < 0.0$ 时，算法自动选择空过。

## 2. 核心问题深度修正

### 🔴 修正点 1: 解耦 `PenaltyWeight` 与参数安全比值区间

- **算法安全区间**: 推荐 $\frac{PenaltyWeight}{CostWeight} \in [0.55, 0.70]$。
    - 默认参数: $CostWeight = 5.0$, $PenaltyWeight = 3.5$ ($\text{比值 } 0.70$)。
    -
    在启动期由 [EngineConfig.kt](file:///g:/liw_work/jiaoBen/Deck-Plugin-Market/WeightHanderStrategy/src/main/kotlin/lin/config/EngineConfig.kt)
    自动校验，若 $PenaltyWeight \ge CostWeight$ 则抛出配置异常，防止极端调参打破平衡。

---

### 🟡 修正点 2: 解决 $\sqrt{a}+\sqrt{b} > \sqrt{a+b}$ 引起的“垃圾卡凑费”问题

由于凹函数 $\sqrt{4} + \sqrt{1} = 2 + 1 = 3 > \sqrt{5} \approx 2.236$，简单累加会让 4+1 组合天然比 5 费单卡高出近 $3.8$
分的基础分，线性扣分 $0.7$ 无法阻止无脑凑卡。

**V2.1 联合抑制方案**：

1. **基础分 Combo 衰减因子 ($\lambda = 0.85$)**：组合中按单卡分值降序排列，第 $i$ 张卡的 $\text{baseScore}$
   乘以 $\lambda^{i-1}$（第 2 张卡打 $8.5$ 折，第 3 张卡打 $7.2$ 折）。
2. **非线性 `comboPenalty`**：
   $$\text{comboPenalty} (n) = (n - 1)^{1.5} \times ComboCardWeight \quad (ComboCardWeight = 0.7)$$
    - $n=1 \rightarrow \mathbf{0.0}$ 分
    - $n=2 \rightarrow \mathbf{0.70}$ 分
    - $n=3 \rightarrow 2^{1.5} \times 0.7 = \mathbf{1.98}$ 分
    - $n=4 \rightarrow 3^{1.5} \times 0.7 = \mathbf{3.64}$ 分（对 4 卡以上的垃圾堆砌施加剧烈惩罚）
3. **负分卡豁免法则**: 当单卡 $\text{extraScore} < 0$ 时，说明该卡已自带副作用惩罚，在 `comboPenalty` 计算中免于二次重复惩罚。

---

### 🟢 修正点 3: 局势主动权 `initiativeScore` 量化矩阵

`initiativeScore` 必须依赖明确的局势量化判定函数，与组合张数轻微挂钩：

$$\text{initiativeScore} = \text{baseInitiative} \times \Big (1 + 0.1 \times (n-1)\Big) \quad (\text{整体上限 } +6.0)$$

#### 局势判定矩阵 (GameState Evaluation Matrix)

```kotlin
// 局势判定逻辑伪代码 (T-124 / G-08 落地)
val myBoardAttack = myMinions.sumOf { it.attack }
val enemyBoardAttack = enemyMinions.sumOf { it.attack }

val situationState = when {
    // 劣势局判定: 敌方场攻 >= 我方 1.3 倍 或 我方血量 <= 10
    enemyBoardAttack >= myBoardAttack * 1.3 || myHeroHp <= 10 -> Situation.DISADVANTAGE
    // 优势局判定: 我方场攻 >= 敌方 1.3 倍 且 我方血量 >= 15 且 敌方随从 <= 3
    myBoardAttack >= enemyBoardAttack * 1.3 && myHeroHp >= 15 && enemyMinions.size <= 3 -> Situation.ADVANTAGE
    // 均势局
    else -> Situation.EVEN
}

val baseInitiative = when (situationState) {
    Situation.ADVANTAGE    -> 3.0  // 优势局：奖励主动铺场/压制 (+3.0)
    Situation.EVEN         -> 1.0  // 均势局：鼓励适度进取 (+1.0)
    Situation.DISADVANTAGE -> 0.0  // 劣势局：强行关闭，优先解场保命 (0.0)
}
```

### 🟣 修正点 4: `ruleScore` 阶梯量规 (含负向规则分)

为了防止动态失误动作（如对满血敌方治疗、对空场打群体解场），引入 **负向规则分阶梯**：

| 阶梯等级           | 给分范围               | 典型战术场景                                         |
|:-------------------|:-----------------------|:-----------------------------------------------------|
| 🔴 **严重失误级**  | **`-8.0 ~ -12.0` 分**  | 无敌方随从时打出群体解场、对满血敌方打出单体治疗     |
| 🟠 **无效/浪费级** | **`-3.0 ~ -5.0` 分**   | 手牌过满时盲目过牌导致烧牌、非关键回合浪费有限资源   |
| 🟢 **微调级**      | **`+2.0 ~ +4.0` 分**   | 顺手出牌偏好、轻微倾向性提升                         |
| 🟡 **战术主力级**  | **`+6.0 ~ +10.0` 分**  | 核心减费组件（如 `BT_020` 奥尔多侍从）、关键过牌检索 |
| 🔵 **战略级**      | **`+12.0 ~ +18.0` 分** | 核心致胜终端准备、紧急解场防暴毙                     |
| 🟣 **胜负/绝杀级** | **`+20.0 ~ +30.0` 分** | **仅限明确胜负条件到达**（本回合直接斩杀）           |

## 3. 工程落地与配置参数规范

| 参数               | 配置文件键名 (`engine.properties`) | 默认值 |                    安全参数约束                     | 说明                                     |
|:-------------------|:-----------------------------------|:------:|:---------------------------------------------------:|:-----------------------------------------|
| `costWeight`       | `scoring.cost.weight`              | `5.0`  |                       $> 0.0$                       | 静态基础分基准                           |
| `penaltyWeight`    | `scoring.penalty.weight`           | `3.5`  | $\frac{penaltyWeight}{costWeight} \in [0.55, 0.70]$ | 解耦扣分系数，启动期自动校验             |
| `comboCardWeight`  | `scoring.combo.card.weight`        | `0.7`  |                      $\ge 0.0$                      | 非线性 $n^{1.5}$ 组合扣分系数            |
| `comboDecayFactor` | `scoring.combo.decay.factor`       | `0.85` |                 $\in [0.80, 0.90]$                  | 组合中第 $i$ 张卡基础分 $8.5$ 折累加衰减 |
| `extraScore`       | `CardWeightInfo.powerWeight`       | `0.0`  |                 $\in [-3.0, +5.0]$                  | 单卡静态配置（负分卡免 comboPenalty）    |
